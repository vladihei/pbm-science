## What the pilot has established

- Direct API ingestion, pagination, raw snapshot preservation, identifier deduplication, and a normalized status model are practical for ClinicalTrials.gov at thousands of candidate rows.
- One broad keyword query can return many irrelevant results. Search-result volume alone is not the number of PBM studies. The pipeline therefore screens explicit intervention terms and holds broad/ambiguous light uses for review.
- Across registries, a single status word cannot be assumed current. The ChiCTR example was still reported as Recruiting despite a displayed recruitment window whose end date had passed and a last refresh more than three months earlier. Keep source status, source update date, recruitment dates, and our retrieval date as separate fields.
- ReBEC's older `/api2/` advanced-search backend returned 404. The user-provided `/busca` query appears to support candidate discovery through embedded search and the user reports it works in their browser; no full result set, native export or current record status has been verified. Use it to find candidate IDs, then check original records and reuse terms individually.
- ChiCTR's record page exposes contact and address fields alongside useful study metadata. The public index must strictly whitelist non-contact fields and link to the original record rather than mirror its entire page.
- ClinicalTrials.gov's [terms and conditions](https://clinicaltrials.gov/about-site/terms-conditions) make its data available without charge and set publication conditions including source attribution, current data, a displayed processing date and a description of modifications; some submitted material may carry third-party rights. The official `/api/v2/version` endpoint supplies `dataTimestamp`; the fetcher now requires a stable timestamp across collection and the site displays it with the retrieval date. The output omits contact details, long submitted descriptions and results narratives. The planned pilot uses only a narrow structured-field extract and a daily refresh, with the source timestamp and retrieval date displayed; this is a practical compliance measure, not legal advice or a guarantee that third-party rights never apply. If the scheduled refresh fails or the required disclosures cannot be maintained, pause publication.
- Direct-source use does not avoid all terms and freshness issues. ANZCTR has its own continuous-currentness and processing-date requirements and restricts unauthorised software collection. ISRCTN's CC0 statement for newer metadata sits alongside a site term limiting database population, so written clarification is needed. DRKS provides a promising daily dated bulk export, but its download terms still need to be read. EMA's general notice permits attributed reuse of EMA-owned material but excludes third-party contributions appearing in the CTIS portal.
- CTIS must be searched separately from historical ICTRP exports: EMA describes its public portal as covering EU/EEA trial information from 31 January 2022. The older EU Clinical Trials Register is the separate source for legacy trials under Directive 2001/20/EC; do not assume a zero ICTRP count means there are no relevant trials there.
- ReBEC, ChiCTR, CTRI, and IRCT remain excluded until their source-by-source reuse reviews and retrieval methods are confirmed. Open access or visibility in a public browser is not treated as redistribution permission. The local encrypted site payload is not yet generated; it will contain only the selected ClinicalTrials.gov extract after the configured workflow runs.

## Repeatability and broad coverage

The recurring query set and source checks are in `search-strategy.json` and `MONTHLY-UPDATE.md`. This month demonstrates a repeatable, timestamped ClinicalTrials.gov-only pilot. ReBEC's earlier `/api2/` advanced-search backend returned 404, while the user-supplied `/busca` route can guide candidate discovery but is not a verified complete registry search or data export. ChiCTR's native search hit a WAF, ANZCTR limits unauthorised automated collection, ISRCTN's database-reuse terms need interpretation, and DRKS requires acceptance of terms before bulk export. CTIS still needs a direct search. A broader international census is not yet demonstrated. The tracker in `registry-coverage.csv` distinguishes prior ICTRP discovery counts, direct source tests and sources not yet cleared for publication.
